# 折り図原本JSON・第1段階／第2段階

対象は `lab/origami/tools/` のみ。アプリ本体、既存作品、既存の作品ビルダや
3Dエンジンは変更しない。既存作品の再生成も行わない。

## 原本と座標

`origami_recipe.schema.json` が `.origami.json` の構造を定義する。
`format: "origami-recipe"`、`version: 1`、
`coordinates: "unfolded-normalized-xy"` が必須。

- 最初の展開状態の紙を、x・yとも `[-1, 1]` に正規化する。
  原点は中央、xは右向き、yは上向き。すべての手で同じ座標を使う。
- `paper.aspectRatio` は幅÷高さ。実計算への変換は
  `(u, v) → (u, v / aspectRatio)`。紙の半幅は常に1。
- `paper.colorDown` は開始時に色面を下にするかを示す。
  生成する作品データに反映する。既存エディタの面色表示は従来どおり。
- `line` は原本上の2点。`reference` の面が持つアフィン変換から
  現在の折り線を導出する。線の端点は参照面の外でもよいが原紙内でなければならない。
- `movingSidePoint` も原本座標。参照面内にあり、折り線上にはない点を指定する。
  現在位置へ変換した点の側を折る。端点の入力順で折る側は変わらない。
- `kind: "V" | "M"` は操作直前に上から見た谷・山。
- `work` は作品情報、`source` は任意の資料名・注記。資料のURLやパスを
  インポート時に取得・実行することはない。

## 面の識別と由来

初期面の `faceId` は `paper`。面が分割された場合だけ子のIDを発行する。
例えば手 `s1` の分割後は `paper/s1.keep` と `paper/s1.cut`。
`keep` は動かない側、`cut` は動く側（creaseでは動かす予定の側）。
単に移動・裏返しした面と、対象外の面は同じIDを維持する。

`layerPath` は分割由来を持つ構造化配列で、動作履歴の文字列や配列添字ではない。
例：`[{"stepId":"s1","side":"cut"}]`。
現時点の重なり順 `layer` とは別の情報。

参照と対象層は、次のどちらでも指定できる。

```json
{"faceId":"paper/s1.cut"}
```

```json
{"faceId":"paper","layerPath":[{"stepId":"s1","side":"cut"}]}
```

完全な子IDと `layerPath` を両方指定した場合は整合性を検証する。
分割済みの親IDだけを指定して子を暗黙に全選択することはしない。
`targets` は現在存在する面の明示リストで、`reference` も含める。
同じ面を重複指定することはできない。

IDは同じ手ID・分割由来に対して再生や保存の前後で安定する。
分割そのものを変更したり手IDを変えた場合に、旧IDが有効であり続ける保証はしない。
この段階では自動的な参照の付け替えは行わない。

## 対応操作と検証

対応するのは `fold`（180度）、`crease`（折り筋を付け、展開状態を保つ）、
`flip`（紙全体の裏返し、`axis: "v" | "h"`）のみ。
`squash`、`open-pocket` を含むその他の操作は未対応エラー。
通常のfoldへの代替や読み飛ばしはしない。

構造検証の後、各手を一時状態で再生する。未知・分割済みの面、由来の不一致、
ゼロ長の線、原紙外の点、参照面外の指定点、対象のない操作などを拒否する。
エラーに手順位置と折り図番号を含める。上限は100手・1024面。
ブラウザで読み込むJSONは2MiB以下。

構造検証器は隣接スキーマが使用するキーワードのみを実装したもの。
任意のJSON Schemaを処理するライブラリではない。
検証成功は、袋の開閉・面同士の衝突・現実の紙の連結性を含む
一般の物理的な折り可能性の保証ではない。

## エディタの原子的インポートと保存

`fold2d_editor.html` の「折順を読み込む」で原本JSONを選ぶ。
スキーマを隣接ファイルからfetchするため、HTTPで開く。
構造検証と全手順の再生に成功してから、状態・タイムラインを一括で切り替える。
途中の不正データ、ファイル読込失敗、読込中の編集、後続の別ファイル選択によって
元の編集結果が部分的に置き換わることはない。

「読み込んだ原本JSONを保存」は取り込んだ原本をそのまま保存する。
途中の面座標へ書き換えず、作品情報・出典・面参照を保持する。
読み込み後の手動編集を新しい原本へ逆変換する機能は第1段階に含めない。
編集した状態で原本保存すると明確なエラーを表示する。
読み込み完了時と同じ状態までundo/redoすれば保存できる。

従来の `{paper, steps}` の読み込み・「折順を保存」は従来形式のまま残す。
旧形式を原本形式と誤認して自動変換しない。

## 第2段階：参照画像と原本の手入力

`fold2d_editor.html` 右側の補助UIを使う。

1. ローカルPNG・JPEG・WebPを読み込み、画像移動モードで左キャンバス上を
   ドラッグする。倍率・透明度・表示切替・位置リセットで図を合わせる。
   画像表示中は紙の塗りを薄くし、下敷きを見えるようにする。
2. 「新規作品の情報」を入力して「新規原本を開始」、または第1段階の
   読み込みで取り込んだJSONに「読み込んだ原本に追加」を選ぶ。
3. 手順ID・図番号・説明・操作を入力する。fold/creaseでは山谷・参照面・
   折線の2点・movingSidePoint・対象層を指定する。対象面を緑で強調する。
   画面の点入力は参照面の逆写像を使い、常に原本座標へ戻す。
4. 「入力を検証・プレビュー」で全手順を一時再生し、折る前／折った後を
   切り替える。折る前の画面には折線と移動矢印を表示する。
   「この手を確定」するまでは編集状態・確定手順を変更しない。
   入力の修正は検証結果を破棄し、再検証を必要とする。
5. 確定済みの末尾だけ追加・取り消しできる。「原本JSONを保存」で
   全手順を検証してv1の `.origami.json` を保存する。0手の下書きは保存不可。

画像を動かすモードでは紙の点を選択しない。原本入力中は従来の上部操作を
停止する。「入力を終了」で確定済み状態を保って従来操作へ戻れる。
従来の自由操作を原本へ自動変換する機能は追加していない。

画像はブラウザのメモリだけに保持し、表示設定も履歴・JSON・ストレージへ
保存しない。ローカル画像は送信せず、`_zu` の原画像を読み込んでも
元ファイルの移動・編集・共有登録はしない。画像名・パス・画素・一時URLを
原本に自動転記しない。読込用の一時URLは画像デコード後に解放する。
画面の再読込で画像は破棄される。画像読込上限は20MiB・4000万画素。

新規作品では任意の注記に出典・作者・利用条件を記入できる。
既存原本のsourceなどのメタデータは第1段階との互換性のため保持する。
画像を含む画面を共有する場合は作者の利用条件を確認する旨をUIに表示する。

未対応：画像の自動解釈、つぶし折り・袋折り、任意角度の折り、
画像の回転・遠近補正、途中手順の編集と参照面の自動修復。

## Python CLI

Python 3.10以降。変換処理に追加pipパッケージは不要。
以下は `lab/origami/` から実行する。

```text
python -B tools/origami_recipe.py tools/recipe_examples/triangle.origami.json --check
python -B tools/origami_recipe.py tools/recipe_examples/triangle.origami.json --output tools/triangle.compiled.json
```

`--check` は構造検証・全手順の再生だけを行い、書き込まない。
`--output` は明示した新規JSONにのみ書き込む。既存パス、`origami/` 外、
`js/` 内への出力は拒否する。アプリへの登録、JSの生成、一括再生成は行わない。

出力は `format: "origami-compiled"`, `version: 1` の包みで、
`recipe`（原本）、`work`（既存 `to_work()` で生成した再生データ）、
`faces`（faceId・layerPath・正規化したsourcePolygon・boneIdの対応）を保持する。
原本にはボーン番号やPythonの折り履歴を記入しない。
生成した包み自体をエディタに渡すことは第1段階の対象外。

## 検証

```text
python -B tools/test_origami_recipe.py
```

Node.jsが必要。Pythonの4テストが、独立した二手の一作品について
面積・既知の最終三角形・重なり・面ID、CLI出力と上書き拒否を確認する。
同じ作品の派生ケース（部分層、山折り、折り筋、裏返し、長方形）でも
PythonとJSの各手の面位置・原本への逆写像・重なり・由来を照合する。

`test_origami_recipe.js` は実際のエディタのスクリプトをNode VMで動かし、
原本の往復、途中失敗の原子性、非同期読込の競合、旧形式の互換性を確認する。
DOMとcanvasはテスト用の代替であり、実ブラウザの描画テストではない。
テスト生成物は `tools/` 下の一時ディレクトリ内に限り、終了時に除去する。
`index.html`・`js/core.js`・既存作品JSがCLIテスト中に変わらないこともハッシュで確認する。

第2段階の確定・検証失敗・末尾取り消し・原本の往復も同じテストに含む。
実Chromeで補助UIを確認する場合は次を実行する（Node.js 22以降）。

```text
node tools/test_origami_authoring_browser.js
```

インストール済みChromeの標準パスを使用する。別のパスの場合は環境変数
`ORIGAMI_CHROME` で指定できる。テストは一時HTTPサーバーとヘッドレスChromeを
起動し、自作の一時PNGで画像の表示・ドラッグ・倍率・透明度を確認する。
手順フォームで二手を作成し、プレビューの非破壊性・反転面からの点入力・
保存と再読込・画像情報の非混入・不正JSON・未対応操作・コンソールを検査する。
`_zu` の画像はテストにも使用しない。プロファイルとダウンロードはOSの
一時ディレクトリで作成して終了時に削除し、画面確認用PNGだけを一時領域に残す。
