# op:'crease'（折り目だけ）の意味と成立の判定（2026-09-15）

## 意味

- `crease` は、**紙を動かさずに、折り目の線を記録する手**です。
  - 選んだ面を線で二つに分け、平らな結び（`crease`）でつなぎます。
  - 置かれ方（xf）と層は変えません。
- **実物で「折って戻す」過程が成り立つことは保証しません。**
  - つる⑦の上の三角のように、剛体の折り（`fold`）では、どの枚数・どちら側・山谷でも裂ける／上に紙が乗る線があります。
  - それでも、実物では紙のたわみで折り目を付けられるので、`crease` として記録できます。
  - その線を実際に折る手（`fold`、花弁折り、袋折り）の成立は、それぞれの手の判定が別に決めます。
- 「折り目を付けてそのまま折る」（2手の複合操作）では、次のように判定が分かれます。
  - 前半の `crease`：この文書の判定
  - 後半の `fold`：必ず `foldability`

## 成立の判定（engine で1つ）

| 段 | 関数 | 見ること |
|---|---|---|
| 芯（面と結びだけ） | `creasableSet(all, bonds, ids, a, b)` | ① 選んだ面の中に、線で二つに分かれる面がある<br>② 線で分かれる面と平らな折り目でつながり、同じ線で分かれる面は、ぜんぶ選ばれている（折り目が紙の途中で途切れない） |
| 場所つき | `creasability(state, ids, a, b, at)` | 芯 ＋ ③ その場所で上から続けて選んでいる（`contiguousAt`＝折りと同じ規則） |

- 同じ判定を、次のすべての段で使います。
  - 提案（画面の成立判定 `E.pendingCheck`）
  - 枚数選び（`setLayers`）
  - 確定（`confirm`、op が `'crease'` のとき）
  - 再生（`replayVersion1` の crease の手）
- 再生は場所を持たないので、①② だけを見ます。
- 折り（`fold`）の判定 `foldability`（上に乗る紙・裂け・続けて選ぶ）は**変えていません**。
  - 変更前と後で `setLayers` の結果が一致することを確認しました（18,944通り）。

## 候補の操作

- `proposeOnFace(…, { op: 'crease' | 'fold' })` で、候補（pending）が操作を持ちます。
  - 画面は、凍結したセッションの「折り目だけ」の設定から渡します。「折り目を引く」は常に `'crease'` です。
  - op を指定しない呼び手は `null` とし、判定は今までどおり折りです。
- `setLayers`・`pendingCheck`・`preview` は、候補の op で判定を選びます。画面は判定の種類を選びません。
- `confirm` は、候補の op と確定の op が食い違えば断ります（op を指定した候補だけ）。

## 枚数（上からN枚）の意味

- 枚数の意味は折りと同じです。
  - この場所の重なりの上から N 層の面を集め、平らな折り目でつながる面を足します（`topFaces`）。
  - **内部の面数と、選ぶ枚数は別です。** 例：つる⑦の上の三角では、上から1枚＝4面（一番上の紙の左右の半分と、凧形の外側の2片）です。

## プレビュー

- 折り目だけの候補で折った姿を見せるのは、「どこに折り目が入るか」の表示のためだけです。
- その姿で結びが開いて見えるときは、平らな姿（0°）で見せます（`shownFlat`）。これは成立の根拠にしません。
- 「折り目を引く」は、指を離したあとも 0° のままです。
