## 🚨 何度も踏んだ地雷（作業前に必ず読む）

### 1. メッシュが裏返る → 真っ黒な塊になる（**6回**踏んだ）
本体パスで裏面カリングされて消え、輪郭パス（表を切って裏を描く）だけが残るため。
- 目のドームの基底が**左手系**だった（列が X×Y≠Z）
- 足のロフトを**下向き(-Y)に作った**
- ロフトの**ふたの巻き順**が逆
- `tubeGeometry` の巻き順がロフトと逆
- `ringGeometry` の巻き順が逆（地面が真っ黒な円ばんに）
- 皿の内外を**形ごと反転**させた（背中あわせのおわん2つになった）

→ **新しいジオメトリを書いたら必ず `fixWinding(pos, nrm, idx)` を通す。**
→ ロフトは必ず +Y 方向に作り、下向きにしたいときは骨/配置の回転で倒す。
→ 内がわ／外がわは「同じ形をうすくずらした2枚」。形を反転させない。

### 2. 背景の置き場所
- **カメラは筒の軸から約9.65（`CAM_AXIS`）離れている。** 距離の基準は必ず「カメラから」。
- 背景は**筒の向こうがわ**（角度に π を足す）に置く。手前に置くと近すぎて巨大化する。
- 置き場所は `bgPlace(depth, lat, elev)` を使う。`depth` は重なり順のためだけで、
  **大きさは実寸と実きょりから `sizeAt()` で出す**（`groundView()` が見上げ角を返す）。

### 3. 縮尺は1つに載らない
200mのビルと半径6371kmの地球は同じ物差しに載らない。3枚を高度で受けわたす。
- 〜約1,400m … **公園の芝生**（`buildParkGroundMesh`。世界に固定＝登ると遠ざかる）
- 400m〜約20万m … **平らな地図**（`buildFlatGroundMesh`。海岸線・山なみ・川）
- 12万m〜 … **地球の球**（`buildEarthMesh`。日本が上を向く）＋ **大気のふち**
- **低いところで球を使うとカメラが球の面に乗り、地面が薄い帯になって下が黒く抜ける。**

### 4. 空のもの（星・星雲・銀河）を置くとき
- **カメラは 0.17rad 見おろしていて、縦の画角は ±0.58rad しかない。**
  見上げ角 0.4 より上に置くと画面の外に出て、二度と見られない（銀河が左上に切れていた）。
  横の画角は **0.34rad** しかないので、2つ並べるものは 0.3rad 以内に置く。
- **画面のどこに映るかは `__cj.skyScreen(向き)` で数えられる。** ただし
  **カメラの行列は次の rAF で作られる**ので、向けた直後ではなく1フレーム描いてから測る。
- **にじみ（グロー）は端を必ず0まで落とす。** 途中で `if (d > …) return` すると
  空に丸い切り口が見える（赤い星のまわりに円のふちが出た）。
- **背景が明るいと暗い岩の足場が沈む。** 広い面（帯・星雲・銀河・にじみ）だけ
  まとめて頭打ちにしてある（`CEIL = 0.20`）。星とビーコンの芯は点なので対象外。
  （0.34 では緩すぎて、実測で空0.358・岩0.368＝コントラスト0.03 だった）

### 5. 実測の落とし穴（今回踏んだ）
- **撮った絵のフォルダを消さずに撮り直すと、前の回の残りを見てしまう。**
  種（seed）が毎回ちがうと、同じ名まえのファイルが別の回のものになる。
  → `tools/sky.py` は毎回フォルダをまっさらにし、**種を固定**するようにした。
  これに気づかず「直したのに絵が変わらない」と30分ほど回り道した。

### 6. 地面と地平線（ここで2回はまった）
- **地面のふちは「本当の地平線」に合わせる。** `Rg = Dg / tan(dip)`。
  勝手な見込み角で決めると、地面のふちだけ下にずれて、
  同じ地面の上にあるはずの**富士山とビルが空に浮く**（本人に指摘された）。
- 逆に、**目の高さのすぐ下に大きな板を置くと画面の下半分が地面になる**。
  はじめ 0.36 下に半径330 を置いていて、**チッチが地面に埋もれて見えた**。
- 平らな地面のもようは **半径の対数**で作る。ふつうに半径で作ると、
  低いところでは外がわの1割しか視野に入らず、海岸線も山も一度も見えない。
- **円ばん（ringGeometry）は頂点が内と外の2周しかない。** 同心に何枚も重ねないと、
  colFn で描いたもようが全部「2色の補間」に潰れる（公園が土一色になった）。
- **大気のからは、カメラの内がわに入れない。** `rs = r + min(r*0.055, (D_E-r)*0.5)`。
  内がわに入ると裏面カリングで丸ごと消える。

### 7. その他
- 顔テクスチャは `UNPACK_FLIP_Y_WEBGL` が要る（無いと顔のオレンジがおなかに出る）
- 足場の**見た目の上のはしは実測値**（`PropBuilder.build()` の `top`）を使う。定数だとチッチが沈む/浮く
- 黒い宇宙に半とうめいを重ねると暗くなる。ガラス（ヘルメット）は**加算合成**
- 単位は必ず小さい順（`AU → 光分` は逆。1光分 < 1AU）
- 高さでメッシュごと引き伸ばす物（ビル）に別パーツの板を貼らない。頂点カラーの帯にする
- テスト用 `warp(m)` は**カメラと足場も一緒に運ぶ**こと（数字だけ進めると別の枠で確認してしまう）
- ポーズの撮影時は rAF ループを止める

## 🖥 画面チカチカ（2回目・2026-08-21）

2. 下がると軽くなる → 「12ms未満＝余裕がある」で段が上がる

「余裕がある」の条件にいつでも当てはまる。**PCでしか出ない。**

- 遊んでいるあいだは **下げることしかしない**（`running` のときは上げない）
- 下げるのは **2回続けて重かったとき**だけ

`Math.min(実時間, 1/20)` で頭打ちにしてあるので、**重い端末ほど「3秒待つ」が
19秒になる**（実測。swiftshaderで一度も段が下がらなかった）。実時間で数えるよう直した。

## ☄️ 彗星（2026-08-21・本人「彗星はやろうよ」）

**空ではなく「もの」として作った。** 彗星は動くので、背景シェーダ（`skyFS`）では表せない。
惑星と同じインスタンスで置き、**加算合成**でにじませる。

- `buildCometMesh(lean)`（`scenery.js`）。しっぽのかたむき違いを3つ焼く
  （`iRot` は **Y軸まわりしか回せない**ので、画面の中での傾きはメッシュに焼くしかない）
- **コマ**＝大きさのちがう球を3枚重ねる。加算なので**重なった枚数がそのまま明るさ**＝にじみになる。
  色が緑白なのは、本物のコマが C₂ という分子で光るから
- **しっぽは2本**。イオンの尾＝まっすぐ・細い・青／ダストの尾＝太く短く・**カーブして遅れる**・黄白
- 出る場所は3つ：**カイパーベルト(11,300〜12,700)／オールトの雲(20,000〜30,000・薄め)／
  巡回の `comet` バイオーム**。★深宇宙の巡回だけに置くと**ふつうに遊んで一度も見られない**。
  それに、彗星が来るのは本当にカイパーとオールト＝事実どおりに置けば届く場所にも出せる
- 入るときは長く（遠くから近づく）、出るときは短く。**13,000 の手前で必ず切る**
  （そこからはヘリオポーズ＝見せ場の前の静けさで、何も出してはいけない）
- 事実を1行だけ置く：「**しっぽは、進む向きではなく、太陽と反対がわへのびる。**」感想は書かない

### 実測でわかった落とし穴

- **`additive` だけではダメで、トゥーン陰影がかかって「黒い円すい」になる。**
  彗星は自分で光っているので、陰影を計算してはいけない。→ `uGlass = 3`（自発光）を新設。
  中身は `vCol * max(dot(N,V),0)`＝**正面ほど明るく、ふちほど暗い**。
  球なら「まん中が明るい玉」、円すいなら「ふちのやわらかいしっぽ」になる
- **`bgPlace` の横のずれ `lat` は ±0.15 まで。** 横の画角が ±0.17rad しかないので、
  0.24 にすると**一度も画面に映らない**（実測でそうなった）
- **2本の尾の角度をしっかり離す**（0.44rad）。近いと明るいイオンの尾に飲まれて「尾は1本」に見える
- 描画コストは測定誤差の範囲（彗星あり 53.2ms／なし 54.8ms・swiftshader）

## 🪨 宇宙の足場のモデリング（2026-08-21）

本人の指示「**宇宙の足場もモデリングしよ**」。4種を作り分けた。

| 種類 | 見わけの決め手 |
|---|---|
| 岩 | **クレーター**（おわん＋ふちの盛りあがり）／上のめんを少し平らに／上に小石3つ |
| 氷 | **六角柱**の結晶を6本（根もとだけ埋める）。三角のトゲでは岩と見わけがつかなかった |
| こわれ | かたまりを広げる＋**暗いくさび**を3本差しこむ（＝ひび） |
| バネ | 平たい岩＋金属のらせん。`springParts(b, null, {dim:0.62})` |

### 実測でわかった落とし穴

- **かたまりを離すと「割れた破片の散らばり」に見える。** すきまを空けず**重ねる**こと。
  `ASTEROID_CHUNKS` を内側へ寄せて、それぞれを大きくした
- **`uFloor` を上げすぎると陰影が全部つぶれて、岩ではなく白い紙きれに見える。**
  0.82 → **0.45**（0.82／0.45／0.0 の3枚を撮って比べた）。背景から浮かせるのと
  形を見せるのは**両立する。ただし 0.5 が上限**
- **粗くすればするほど結晶らしくなる、はウソ。** 氷の土台を `sphereGeometry(5,3)` まで
  粗くしたら「割れたガラスの破片」になって、乗れる足場に見えなくなった → `(8,6)`
- **バネのらせんを 2.1倍のまま宇宙で描くと、色が振り切れてのっぺりした塊になる。**
  `dim` で落とすと、陰影＝らせんの形が出る

## 🪖 「黒いかぶりもの」の正体（2026-08-21・4回目）

ヘルメットが黒いカツラに見える件、原因は**合成でも裏返りでもなかった**。
