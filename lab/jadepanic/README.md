# ジェイドパニック — JADE PANIC

オトン学園の**ミニゲーム**として作った、ネオンのツインスティック・シューター。
`Geometry Wars: Retro Evolved 2` の設計思想（ジオムを拾って倍率を上げる＝攻めるほど点が伸びる）を、
オトン学園のキャラ **ジェイド**（コガネメキシコインコ）を主役に作り直したもの。

**本体（`tuna app/index.html` ほか）には まだ一切 手を入れていない。** ここだけで完結して動く。
組みこみ方は最後の章にまとめてある。

- **ゲームパッド**：左スティック移動・右スティック射撃・R1/R2 ボム。

## 世界観

> オトン学園のデータの中に、**バグ**がわいた。
> 図鑑のなかまでデータの空を飛べるのは、コガネメキシコインコの**ジェイド**だけ。
> こわれていく光の格子を、ジェイドが飛びまわってそうじする。

- 敵＝**バグ**（7種）。倒すと**ビット**（みどりの小さなかけら）がこぼれる。
- **ビット1つで ばいりつ +1。上限なし**（本家GW2と同じ。×200、×900も出る）。
- **やられても ばいりつは減らない**（本家仕様。一度のミスで戦意を失わないため）。
- ビットはほとんど寄ってこない（磁力 やさしい140／ふつう95／むずかしい55）。
  **逃げてばかりでは点が伸びない＝敵の群れに飛びこむ**のがこのゲームの背骨。
- ボムは**大はばたき**。画面じゅうのバグを吹きとばし、ビットを全部引き寄せる
  ＝**ばいりつを一気に跳ね上げるチャンス**（本家の定石をそのまま採用）。
- 残機とボムは **点の桁が1つ上がるごと**（10万→100万→1000万…）。

## モード

| モード | ルール |
|---|---|
| **サバイバル** | 残機がなくなるまで。時間が経つほど敵の種類と数が増える |
| **60びょう** | 60秒のスコアアタック。ミスは残機ではなく **−5秒**。敵の解禁が約4.5倍速 |

難易度は やさしい／ふつう／むずかしい の3段。変わるのは
**残機・湧きの勢い・同時に出る数・敵の速さ・ビットの磁力**（倍率の減り方は3段とも「減らない」）。

### 描画のしくみ（ここが肝）

**画面のすべてが「線分（カプセル）」でできている。**
ジェイドも、バグも、弾も、粒子も、ゆがむグリッドも、同じ1本のインスタンス描画に相乗りする。
→ **シーンの描画ドローコールは1回**（毎フレーム 3,000〜5,500インスタンス）。

- 線分は頂点シェーダで四角に展開し、フラグメントでカプセルまでの距離を測って
  「色のにじみ（`exp(-3.2d²)`）＋白い芯（`(1-d)⁷`）」を描く。加算合成。
- 画面上で最低 1.1px の太さを保証（スマホで細い線が消えないように）。
- HDR（RGBA16F）→ しきい値 → 1/2・1/4 のぼかし → ACESトーンマップ。
  色収差・ビネット・グレイン・**衝撃波のUV歪み**・画面フラッシュは合成パスに統合。
- fpsを見て**解像度を自動で上下**（`R.setQuality`）。`devicePixelRatio` は 2.0 で頭打ち。

### 気持ちよさのために入れたもの

- **ヒットストップ**（大物撃破45ms／ボム75ms／被弾110ms）＋**スローモーション**（被弾0.5秒）
- 画面ゆれは**頭打ちつきのトラウマ値**（`shake^1.5`。何十匹まとめて倒しても暴れない）／**衝撃波が画面のUVをゆがめる**
- 敵撃破でグリッドを押す／バグホールはグリッドを吸い寄せる／ジェイドが通ると少しへこむ
- **BGMのキックの発音時刻を映像に渡し**、背景・グリッド・ブルームが4つ打ちで脈打つ
- ビットをついばむ音は**倍率が上がるほど音階が上がる**（Aマイナー音階を登っていく）
- 湧く前に必ず**破線の予告リング**（0.7秒）。ジェイドから260以上離れた所にしか湧かず、
  実体化の瞬間に重なっていたら外へ押し出す（理不尽な即死をゼロにするため）
- ピンチになると画面のふちが赤くにじみ、背景にブロックノイズ（＝バグの侵食）が走る
- **✨演出トグル**：ゆれ45%・ブルーム減・色収差ほぼ切・グレイン0・衝撃波弱

### やりとり（postMessage）— 子側は実装ずみ

| 向き | メッセージ | 意味 |
|---|---|---|
| 子→親 | `jp-ready` | 起動した。親はニックネームを返す |
| 親→子 | `jp-name` `{name}` | 本体のニックネームをランキングの名前に使う |
| 子→親 | `jp-start-request` | プレイを始めたい（スタート／もう一回） |
| 親→子 | `jp-start-ok` / `jp-start-deny` `{msg}` | 遊び券を消費できたか |
| 子→親 | `jp-score` `{score, mode, diff}` | ゲームオーバーのスコア |
| 子→親 | `jp-rank-request` `{mode, diff}` | クラウドのランキングがほしい |
| 親→子 | `jp-rank-data` `{list}` | `[{nickname, value}, …]` を渡すと結果画面に出る |
| 子→親 | `jp-exit` | 「‹ もどる」→ 親が iframe を `about:blank` に |

- 親が1.2秒返事をしないときは、子が自分で開始する（お試しモードで止まらないように）。
- スコアは `jadepanic_surv_normal` のように**モードと難易度ごと**に分けて保存している。
- **遊び券の枚数は親から `jp-name` に乗せて教える**（子に文字で書くと二重管理になる。
  最初「3まい」とテトリス2から写したまま出ていた）。

## 既知の制約

- ヘッドレスChromium（SwiftShader）では 25〜35fps しか出ない。**実機GPUでの計測はまだ**。
  `EXT_color_buffer_half_float` が無い端末では RGBA8 に落ちる（動作は確認ずみ）。
- 実機iPhoneでの60fps確認と、実際の指での操作感の確認はこれから。

# 2026-08-22 の作り直し（GW2水準への引き上げ）

目標は「**Geometry Wars: Retro Evolved 2 に匹敵する画質**」。
やり方は **ブラインドA/B**：同じ場面を描き方だけ変えて2枚撮り、甲／乙にランダム割りふりして、
1シーンにつき1体の判定役に「どちらが上か」を当てる（どちらが新しいかは伝えない）。
最後の通し判定で **6シーン全勝**、GW2を90点としたときの平均点は **55.7 → 76.5**。

## 画づくりで効いたこと（効いた順）

1. **線ごとに「白い芯の量」を持たせた**（インスタンスに `i_core` を追加、`R.coreMul` で切りかえ）。
   グリッド 0.06 ／ かべ 0.34 ／ 主役 1.0。
   **前は 全部の線に同じ白い芯が乗っていて、背景のグリッドが画面でいちばん明るかった。**
2. **ブルームをミップ・ピラミッドに**。1/2〜1/64 の6段へ落としてから、テント9タップで足しながら戻す
   （1段目だけ soft-knee のしきい値と Karis平均）。ぼかし2段では「遠くまでにじむ光」は出ない。
3. **色を残すトーンマップ**。RGBを別々に圧縮すると 明るい所が全部 真っ白になって、
   爆発の中の敵も自機も消える。**いちばん強いチャンネルだけ圧縮して 残りを比率で戻す。**
4. **背景をほぼ黒に**して、遠くの粒を3層。**黒が濁ると ネオンは立たない。**
5. **グリッドは かべの外へ向けて消す**（`Grid.draw(..., fw, fh)`）＝「盤外」ができる。
   **歪みは形ではなく光の量で見せる**（引きちぎられた所ほど明るく）。
6. **弾**＝太いカプセル3本 → 細く長い光の筋。3発を前後にずらし、外の2発を細く短くした
   （きれいに横並びだと「≡」の記号に見える）。
7. **拾いもの**＝白い四角 → **純緑(#4dff5c)のひし形（輪郭だけ）**。
   ミントは水色の敵と、ライムは黄緑のドッジャーと かぶった。純緑が どちらからも いちばん遠い。
8. **粒子**＝速さを「たまに うんと遠くへ飛ぶ」分布に。長さ・寿命・色をばらし、生まれた瞬間だけ白く焼く。
9. **自機のあしあと（軌跡）**＋常時の小さな白い芯＝混戦で自分を見失わない。
10. **ジェイドの翼を「閉じた多角形」から「V字に開いた2本の線」へ。** 閉じていると輪っかに見えて鳥に読めない。
11. **ワーム**＝白い数珠 → 頭がくさび形・胴はうしろほど暗い色のグラデーション＋節をつなぐ胴の線。
12. 危険演出の**四角いブロックノイズは「描画バグ」に見える** → 横に走るグリッチ帯へ。かべの外だけに出す。
13. 8bit出力の階調段差は**ディザ**で消す。ボムは**全画面ホワイトアウト＋二重の衝撃波リング**。

## すみっこ待ちを つぶした（実測）

`node lab/jadepanic/tools/camptest.js lab/jadepanic/js <秒> <難易度>` で測れる。**「隅から動かず 一番近い敵を撃つだけ」**のお手本プレイヤー。

| | 元 | 直した後 |
|---|---|---|
| 脅威が来る角度（すみっこ） | **22〜38度** | **106〜111度** |
| 参考：ふつうに動いたとき | 77〜102度 | 77〜102度 |
| すみっこに居られた割合 | 99% | 70% |
| 隅からの平均距離 | 7px | 187px |

原因は「すみっこだと 敵が22〜38度の扇からしか来ない」こと。直したのは3つ:
- **かべが押し返す**（3秒で効きはじめ、7秒で自機の最高速を超える。かべが赤く焼けて理由が分かる）
- **湧きが自機のまわりを囲む**（`cornerT` が長いほど 自機基準の湧きの比率が上がる）
- **バグホールが自機も吸う**

⚠ **追い出しで敵を「増やす」と、すみっこ待ちがいちばん点の伸びる戦法になってしまう**（実測で逆転した）。
`flushSpawn()` は `spawnDebt` でふだんの湧きから前借りし、**総量を変えない**。

## 敵の個性＝動きのリズム（形ではなく）

ノイズ＝漂うだけ（こっちを見ていない）／チェイサー＝**脈を打って踏みこむ**（形も前へ伸びる）／
スピナー＝速さを落とさず かべで硬く跳ねる／ドッジャー＝**正面から来ず まわりを回る**／
ワーム＝大きくうねって盤を横切る／ぶんれつ＝短く突っこんでは向きを変える／バグホール＝自機も引っぱる。

## 自動ねらい（かんたん）が効いていなかった

**狙いの計算ではなく 入力の問題だった。** PCでは `Input.gather()` がマウスの向きを毎フレーム `ax/ay` に入れるため、
`al > 0.25` の手動分岐が常に勝ち、**自動ねらいの分岐に一度も入らなかった**。
→ `autoAim` のときは `ax/ay` を 0 にする。あわせて `pickAutoTarget()` を追加し、
「近い」「いま向いている方に近い」「さっきと同じ相手」を点数にして選ぶ（毎フレーム選び直すと狙いが振れて当たらない）。

実測（マウスを動かした状態での、一番近い敵と狙いのズレ）: **元 58度 → 直した後 1度**。
`node lab/jadepanic/tools/aimtest.js lab/jadepanic/js` で 自動と「完璧な手動」を比べられる。

## バグホールの合体（2026-08-29）

**前は、バグホールどうしがぶつかると 両方 消えていた**（本人が遊んで指摘）。
「いちばん強い敵が 勝手に消える」＝倒す気持ちも 避ける緊張も 無くなる。
→ **消さずに 合体させて 上の段へ育てる**（`HOLE_TIER` = バグホール → メガホール → ギガホール）。

- 合体すると **その段の体力で出なおす**（22 → 48 → 92）。大きさ・引力・吐き出す数・点・ビットも 段ごとに上がる
- 上限（ギガ）どうしがぶつかったときも **消えない**。体力はそのままで さらに大きく育つ
- ⚠ **合体した先が自機に重なると 理不尽な即死になる**ので、重なっていたら ホールを外へ押しやる（湧きの `shove` と同じ考え方）
- 素の体力も 12 → 22 に上げた（本人「もう少し固くしてほしい」）
- 見た目は **色ではなく 輪の数・太さ・渦の本数**で段を出す。赤系の色を増やすと 他の敵とかぶる（下の「落とし穴4」）

⚠ 実装で踏んだバグ：合体で消えるほうを `holes` 配列から外すとき、**残るほうの番号で splice していた**。
そのせいで 3体目がぶつかると ホールが全部 消えた。`node tools/holetest.js js` で捕まえた。

|---|---|
| `tools/holetest.js` | 合体の検査。2体→メガ、3体目→ギガ、上限どうしでも消えない、点・ビット・かたさ（何秒撃てば壊れるか） |
