## 3. 面データの作りなおしかた

```bash
cd "tuna app"
python lab/okatazuke/tools/make_levels.py      # → lab/okatazuke/js/levels.js
```

`make_levels.py` は
1. 自作の教える面（`tools/levels_src.txt`）を読む
2. 取りこんだ面（`tools/_imported.json`）を読む
3. **同じ物差し**（`tools/difficulty.py`）で むずかしさを測る
4. むずかしさの順に ならべて 4段（やさしい／ふつう／むずかしい／ゲキむず）に分ける
5. **1面でも「解けない」ものがあれば levels.js を書かない**

面集を取りこみ直すとき：

```bash
python lab/okatazuke/tools/import_sg.py <面データ.txt> <解答集.txt> _imported.json 22000
```

- 解答の手順を **実際に動かしてクリアになるか** 確かめる（＝検算）。合わない面は落とす
- むずかしさを測る。ソルバーが上限まで調べても解けない面は `capped` の印をつけ、
  手数・にもつ・詰む手の割合で 順番を決める

## 4. むずかしさの物差し（`tools/difficulty.py`）

資料（村瀬・松原・平賀 1998／Iso-nyang氏「オリジナルステージの作り方」）から起こした。

```
むずかしさ = 3.4·log2(調べた盤面数+1) + 6.0·log2(おした数+1)
           + 2.6·にもつの数 + 26.0·詰む手の割合 + 2.0·おきばのせまさ
```

- **調べた盤面数**（ソルバーの探索の広さ）＝資料がいちばん重く見ている指標
- **おした数**は対数。まっすぐ200回おすだけの面が、40手のひねった面より上に来ないように
- **詰む手の割合**＝手順の各時点で「押したら二度と戻せない手」が何割あるか。
  うっかりで壊れやすい面ほど 人は難しく感じる
- **おきばのせまさ**＝おきばが かべに接している数の平均（融通のなさ）

★重みを変えるときは、必ず 全面を測り直して 並びを見ること。

## 5. 検証の道具（`tools/`）

| 道具 | 何を見るか |
|---|---|
| `sokoban.py` | ソルバー本体（A*・詰み枝刈り）。`python sokoban.py <面.txt>` で一覧検算。**時間制限つき**（大きい面は 盤面数の上限だけだと 何十分も張りつく） |
| `difficulty.py` | むずかしさの実測。`python difficulty.py <面.txt>` |
| `make_levels.py` | levels.js を作る（全面の検算つき） |
| `import_sg.py` | 面集の取りこみ＋検算＋実測 |
| `check.py` | **ふるまいの検証**（下記）。いちばん大事 |
| `play.py` | 実際に遊んで 絵を撮る（ソルバーの手順どおりに動かしてクリアまで） |
| `shot.py` | オカンのモデルを角度別に撮る（`preview.html`） |
| `embed_check.py` | 本体に組みこんだ状態を 指のタップで確かめる |
| `gen.py` / `farm*.py` / `curate.py` | 自作面の生成（逆行作成法＋採点＋山のぼり） |

`check.py` が見るもの：
1. 全面が よみこめて にもつ＝おきばの数が合っているか
2. **もどす**を n 回で 最初の配置に ぴったり戻るか
3. **やりなおし**で 戻るか
4. **詰み判定が本当に正しいか**（JSが「詰み」と言った局面を Python のソルバーにかけて、
   本当に解けないことを裏どりする）★まちがって「詰み」と言うと 子どもが混乱する
5. タップで歩く が動くか

動かしかた（先にサーバを立てる）:
```bash
cd "tuna app" && python -m http.server 8899 &
python lab/okatazuke/tools/check.py
python lab/okatazuke/tools/play.py
```

## 8. 踏んだ地雷（同じ穴に落ちないように）

1. **外周のマスに にもつを置くと 詰みになる面ができる。**
   かべに接したマスの荷物は かべにそってしか動かせない。手で面を作ったとき **4面もこれで壊した**。
   → 必ず `make_levels.py`（ソルバー）に通す
2. **髪を「房」で並べると 顔の前に板が立ちならぶ。**
   頭より ひとまわり大きい かぶせものを作り、**断面を高さごとに前後させて**
   目の高さだけ後ろへ引く＝顔の窓。まん丸を後ろへずらす方式では 顔が全部かくれた
3. **`#screen-okatazuke iframe` のCSSを書き忘れると 300×150 のまま出る。**
   見た目が壊れるだけでなく **中のボタンの当たり判定もずれる**
4. **本体のログインボーナス（`gami-modal`）が開いたままだと 画面ぜんぶを おおう。**
   検査で iframe の中のボタンが押せず 1時間 溶かした。テストでは先に閉じる
5. **本体は Service Worker が入れかわると `location.reload()` する。**
   検査中に勝手に読みなおされる。テストでは `navigator.serviceWorker.register` を潰す
6. **入力を捨てない。** アニメ中の入力をキューに入れず捨てていて、
   ソルバーの手順を流したら **2手 落ちた**（＝子どもの「押したのに動かへん」）
7. **おきばの板を タイルの中に埋めていた**（y=0.005 で タイル上面が y=0.05）。
   実測の絵を見るまで気づけなかった

### 仕組み（触る前に読む）

- Tripoのモデルは**すでに11個の塊に分かれている**（連結成分）。髪・顔・リボン→`HEAD`、鳥→`CHI`、
  手→`ALF`/`ARF`、脚とくつ→`LL`/`LR`。**上着だけが胴と両袖で一体**
- 上着は**切らずに骨2本の重みでなじませる**（シェーダの `aBone.x/y` と `.z/w`）。切ると断面に穴があく
- 重みは「腕の線までの距離」と「背骨までの距離」の比。**骨は太さのある棒として測る**。
  線のまま測ると胸の表面が背骨から遠いと判定され、胴がほぼ全部腕になる（`TORSO` が1頂点だけ残った）
- **逆バインド（ワールド→骨ローカル）は JS 側の `buildOkanFromModel` でやる。**
  Python に骨の式を書き写すと、`OkanRig` を直したとき黙ってズレる。同じ `OkanRig` を呼ぶこと
- 逆行列は「骨ごと」ではなく**頂点ごとに混ぜた行列**にかける（シェーダが `sk = ΣwB` なので）
- `OkanRig` は `new OkanRig(dims)` で支点を差しかえられるようにした。手組みは `OKD`、
  取りこんだモデルは `OKAN_MODEL.dims`。**動きの式（ふり幅・タイミング）は共通**

### 踏んだ地雷（このモデル特有）

1. **手を脚と取りちがえる。** 高さだけで分けると手(Y0.19〜0.35)と脚(Y0.05〜0.26)が重なる。
   → 左右それぞれで「いちばん外に張り出している塊」を手とする
2. **腕を大きくふると肩まわりの布が裂けて黒い板になる。** このモデルは**脇が閉じている**（腕が体に密着）。
   よろこぶ134°・おす73°で発生 → `dims.armSwingMax = 0.75`（43°）で頭打ちにした。歩き(0.55)には影響しない。
   **★脇の開いたAポーズで作り直せば、この上限は外せる。**
3. **画素の比較では退行を判定できない。** 同じコードで2回撮っても最大3%ちがう（アイドルの揺れと跳ねの位相）。
   → 手組みオカンの退行検査は**骨の行列の数値**で見た。432状態 × 骨10本 × 16要素で**差0**（退行なし）

### 🆕 テクスチャの描きなおし（2026-08-24・本人の指摘で追加）

本人から「たすきの字は **復習は宝／できるで！**」「チッチが変」「オカン学園がつぶれてる」。
Tripo が参考画像から焼いた文字は にじんでいて読めなかったので、**UVの上に描き直した**。

```bash
python tools/fix_tex.py            # 直して okan_tex.jpg を書きかえる（768pxで書き出し）
python tools/fix_tex.py --dry      # 書かずに tools/_tex/okan_tex_fixed.jpg だけ
python tools/uvmap.py              # どの骨が UV のどこか を一覧で見る
```

- **元絵は `okan_tex.jpg.bak`（1024・Tripoが焼いたまま）。`fix_tex.py` は毎回そこから作り直す。**
  書きかえた絵から始めると、走らせるたびに 文字の上に文字を描いて 汚れていく
- **島は番号で決め打ちしない。「体のどこにあるか」で選ぶ**（`uvmap.island_info` の中心座標）。
  モデルを作り直しても 同じ場所が選ばれる
- 文字の向きは `uvmap.dir_in_uv(M, tris, 軸)`。体の +Y／+X が **UVのどっち向きか**を
  三角形ごとのヤコビアンから出して 平均する

**ここで踏んだ地雷（5つとも実測で分かった）**

1. **島＝帯ではない。** たすきの島には 上着の白い布も入っている。
   島の真ん中に描くと 胸いっぱいに巨大な文字が出る → **ピンクの帯を色で抜いて**その上だけに描く
2. **古い文字は「ピンクを塗る」だけでは消えない。** 白い文字はピンクではないので残る
   → かたまりの**内がわの穴も埋めてから**塗りつぶす（`fill_holes`）
3. **`fill_holes` の ふちを 0 にすると 全部が穴になる。** 外から たどれず「全部 内がわ」判定
4. **古いロゴは 別の島にも乗っている。** 帽子は 1島だけ消しても 左上に残った
   → 高さ（y>1.02）でも選んで もう一度消す
5. **その高さの選びかたに チッチが入る**（鳥も y>1.02）。骨で のぞかないと **鳥の顔まで白く塗る**

### 🎵 音楽（2026-08-24 追加・`js/bgm.js`）

WebAudio でその場で合成。**曲はぜんぶ自作**（ハ長調・92拍／分・8小節でひと回り＝約21秒。
和音は C→Am→F→G）。音のファイルは持たない。

- **あそび中は旋律を鳴らさない。** 和音とベースと まばらな鈴だけ。
  ★パズルの音楽でいちばん大事なのは「考えているあいだ 邪魔をしない」こと。
  30分ねばる面があるので、にぎやかにすると つらくなる
- タイトルと 面えらびは 旋律あり。クリアで ひとこと 明るくなる（`OKBgm.flourish()`）
- `OKSnd.ctx()` で **効果音と同じ AudioContext を分けあう**

### 😊 表情（2026-08-24 追加・`js/okan_faces.js` ＋ `OkanFace`）

Tripo の顔は テクスチャに焼きこまれていて 1種類しかない。
そこで **目と口の四角だけ** 実行時に貼りかえる（`texSubImage2D`）。6種で 56KB。

```bash
python tools/face_map.py --show    # 目・口が テクスチャのどこかを測る
python tools/face_expr.py --show   # 表情を作って js/okan_faces.js を書く
```

| 表情 | いつ出るか |
|---|---|
| normal | ふつう（まばたきが 3〜6秒に1回 入る） |
| smile | 歩いているとき・タイトル |
| effort | にもつを おしているとき |
| happy | クリア・タイトルで手をふるとき |
| sad | 詰んだとき |
| blink | まばたき |

**★いちばんの勘どころ：顔は UV の継ぎ目をまたいでいる。**
テクスチャに直接 目を描こうとすると 片目の四角が 203x497 に化けた（＝2か所にちぎれている）。
なので **「正面から見た絵」を自前でラスタライズして そこに描き、画素ごとに UV へ戻す**。
`tools/face_map.py` の `rasterize()` が その対応表を作っている。

ほかに踏んだところ：
- ラスタライズの**背景を黒にすると 背景まるごとが「目」になる**（黒いかたまりを目とみなすため）。
  どの判定にも当たらない色（まっ緑）にしておく
- 目と髪の見分けは **「中に白いハイライトがあるか」**。まゆ毛は細長くて白が無い
- 口は **「両目のあいだ・両目より下」**。入れないと ほっぺの赤みを拾う
- 消すときは **べた塗りにしない**。顔の陰影の中に「四角い明るい板」が浮く。
  四角のふちの色を たてよこで混ぜて うめる（`clear_soft`）
- 貼りかえは `renderer.updateTexRect()`。**もとのテクスチャは `UNPACK_FLIP_Y_WEBGL=true`
  で貼ってあるので、貼る位置は 下から数えた y**。ここを間違えると 顔が別の場所に出る

### 踏んだ落とし穴
1. **`gltfpack -sa` を付けてはいけない。** UVの継ぎ目を無視して縮めるので **顔と服がまざった迷彩**になる。
   見くらべ＝`tools/_chars/_uvtest.png`。`-sa` なしでも 97万→6千まで落ちた
   （42,000で止まったのは 実写スキャンのレンガのときだけ。モデルによる）
2. **Tポーズのまま入れると 腕を水平にしたまま歩く。** 骨があるので 焼きなおしてから入れる
3. **`makeMesh`/`makeInstanced` は バッファを作る前に `gl.bindVertexArray(null)` が要る。**
   `ELEMENT_ARRAY_BUFFER` の bind は「いま結ばれているVAO」に記録されるので、
   前のフレームのVAOが残ったまま新しいメッシュを作ると **そのVAOのインデックスがすりかわる**。
   → キャラを途中で入れかえると **ペットが緑と紫の破片になった**。
   起動時は まだ1回も描いていないので出ない＝**「起動では出ないが 切りかえで出る」不具合**
4. UVのVは **そのまま行番号**（`1-v` にすると迷彩に見える）。取りこみ時に一度だけ反転して渡す
5. えらぶボタンは **横スクロールにしない**（5人目が画面の外に出る）。おりかえして全員見せる
6. `OKSnd.tap()` は無い（`step()`）。無い関数を呼ぶと **onclick が丸ごと死ぬ**

## 🦿 動きを 作り直した（2026-08-25）

本人の指摘は3つ。**「肩が外れる」「モーションがぎこちない」「稼働部位のポリゴンが
変わらないとレゴみたいになる」**。当てずっぽうの sin をやめて、順に直した。

### ① 骨を 10本 → 17本
`CHEST`（胸）／`ALS·ARS`（鎖骨）／`LLK·LRK`（ひざ）／`LLF·LRF`（足くび）を追加。
- **鎖骨が 腕の上げ下げの3割ついていく**＝肩が裂けない（前は 上腕だけ回していた）
- **胸と腰を分けた**＝歩くと 上体が 腰と逆にひねれる
- **ひざと足くび**＝棒足でなくなる

### ② 支点は モデルの実データ（`dims.p`）
`import_char_glb.py` が **骨の支点そのもの**（waist/chest/head/clav/arm/elbow/hand/hip/knee/foot）を
書き出し、リグは **親からの差だけ**で組む。`+0.008` のような つじつま合わせが消えた。
★`dims.p` が無い場合（手組みオカン）は `okPivots()` が 昔の寸法から作る。

### ③ 歩きは 標準の関節角の曲線
`lab/_lib/motion.js` の `MOTION.GAIT`（正常歩行の hip/knee/ankle）。
**ひざが1周期に2回曲がる「二段膝」**が 効く。これが無いと 竹馬の歩きに見える。
**歩調は「進んだ距離」から出す**（`MOTION.Phase`）＝足が地面をすべらない。

### ④ スキニングを 2本 → **4本**
これが「レゴみたい」の正体。モデルは 4本ぶんの重みを持っているのに、
シェーダが2本までで **捨てていた**。`aBone2` を足して 4本混ぜる。
実測：3本以上を使う頂点は **全体の3〜4割**（ひじ・ひざ・肩がそこ）。
★`makeMesh` は `data.bone2` が無ければ 0で埋めるので、古い部品も そのまま動く。

### ⑤ ペットに 骨を入れた（羽ばたく）
`import_pet_glb.py` を作り直し。7本＝からだ／左右の羽（内・外）／あたま／しっぽ。
- Tripo は **羽を名前なしの `bone_N` のくさり**で出す → **横（X）へ伸びる くさり**で見分ける
- **脚を羽とまちがえた。**Tripo は 脚を `0_Left_Limb_*` と名づけるので 名前で外す
- **体まで 羽の骨にぶらさがっている**ことがある（ジェイド）→
  `|X| ≥ いちばん外の3割` の節だけ 羽にする。45%を超えたら 警告を出す
- 羽ばたきは **上げが速く 下ろしがゆっくり**。**外の羽は 内より遅れて追う**（`MOTION.spring`）＝しなる

### 🧰 動きエンジン `lab/_lib/motion.js`（共通）
ほかのゲームでも 使う前提。**描画にも モデルにも よりかからない。**
`curve` / `GAIT` / `Phase`（距離で歩調）／ `spring` / `Chain`（しっぽ・羽の遅れ）／
`ik2`（2本骨のIK）／ `Blend`。**ここに書いたものを ゲーム側に 書き写さない。**
