# OCR — 何に使う道具か（**使い道が2つある。混ぜない**）

| 使い道 | 何のために | どのページを取るか |
|---|---|---|
| **① 解法の突き合わせ（本命）** | **すでに実装した大問の解法が、原本の印刷どおりか**を確かめる。原簿に解法を残していなかった時期のぶんが大量にあり、**画像を全部読み直すとトークンが際限なくかかる**。OCRなら文字で機械的に照合できる | 🚨**解答冊子を取る**（ここが本体）。道具は `scripts/ocr_match.py` |
| **② G1の転記の下書き（おまけ）** | 新しく原簿化するとき、設問の転記を楽にする | **問題ページだけ**。文章題の回だけ |

🚨**①と②で「取るページ」が逆になる。**②の理由（解答ページは分数と `÷` が壊れる）を
①に持ちこんで「解答は取らない」と決めてはいけない。**①では解答冊子こそが目的**で、
壊れ方は `ocr_match.py` の設計が吸収する（**白黒を決める道具ではなく、画像で見るべきものを絞る道具**。
食いちがいと出たものだけ画像で確かめる＝安全側に転ぶ）。
→ 2026-09-13、私が②の実測だけで「解答ページは取らない」と決めかけ、本人に取り消された。

## 🚦 いまの運用（本人の判断 2026-09-13）

**②（G1の下書き）は当面いらない。**新方式のG1が**印刷された解法をその場で原簿に残している**ので、
あとから解法を突き合わせる必要が減っていく（＝穴が増えなくなった）。
**OCRの出番は①＝すでに実装ずみのぶんのチェックで、そのときは解答冊子がメイン。**

- だから**新しい教材を原簿化するとき、OCRを取らずに始めてよい**（画像だけで回る。実測ずみ）。
- 取るとしたら**文章題の回の問題ページだけ**。迷ったら取らない方に倒す。

## 🚦 ②で取る範囲（**本人承認 2026-09-13**）

**「問題ページだけ・文章量の多い回だけ取る。解答ページはG1のためには取らない。」**
（①の解法チェックで解答冊子を取るのは別の話。上の表を見ること）

| 取る | 取らない |
|---|---|
| **文章題の回の問題ページ**（速さ・割合・文章題など。転記のたたき台になる） | **解答ページは全部**（分数と `÷` が壊れる。第3分冊では43ページ取って**全部捨てた**） |
| | **図形の回**（図はOCRに写らない。設問が短く、結局画像を見る） |
| | 解説ページ（題名だけならしおり＝`get_toc()` から取れる） |

**根拠（2026-09-13の実測）**
- 解答ページのOCRは、5人の担当全員が「見なかった／じゃまだった」と報告した。
- 図形の回（No.26）は、OCRがあっても担当は結局ほぼ画像を読んでいる。
- 取得は**81ページで50.3分**かかり、直列なので回の先回りができないと待ちになる。
- 効いたのは**文章量の多い回の問題ページ**だけ（「原本とほぼ一致」＝転記のたたき台）。
  ただし `□`→`口`、`甲地`→`印地`、`長`の脱落など**誤読は必ず混じる**ので、
  **画像との照合は省けない**（省いた瞬間に原本と別物になる）。

## 親の手順（G1を投げる前）

```bash
# ① 何が足りないか数える（外部送信なし・保存ずみなら取らない）
python scripts/ocr_pages.py plan "<問題PDF>" 12 16 18 20
python scripts/ocr_pages.py plan "<解答PDF>" 6 8 9 10

# ② 足りないページだけ取る（★外部へ画像を送る。実行前に本人へ報告する）
python scripts/ocr_pages.py fetch "<問題PDF>" 12 16 18 20 --measure docs/_genbo/<作業>/_MEASURE.md

# ③ 担当ぶんだけ切り出す（外部送信なし）。担当1人につき1ファイル
python scripts/ocr_pages.py slice "<問題PDF>" 12 16 --out docs/_genbo/<作業>/ocr/A_mondai.md
python scripts/ocr_pages.py slice "<解答PDF>" 6 8  --out docs/_genbo/<作業>/ocr/A_kaitou.md
```

- **保存ずみのOCRは取り直さない。**本ごとに `docs/_genbo/_ocr/<PDF名>.json` に貯める。
  すでに別の場所にあるものは `ocr_pages.py` の `ALIASES` で拾う（例：`g5enshu3/_ocr_mondai.json`）。
  **別の本に同じページ番号があるので、貯め先とOCR台帳は必ず本ごとに分ける。**
- **全冊は渡さない。**担当範囲の問題ページ・解答ページだけを、**PDFページ番号つき**で渡す。
- **OCR取得の時間は、G1の処理時間と分けて記録する。**`fetch` が
  `docs/_genbo/_ocr/_TIME.md` に1行足す（`--measure` を付ければ作業側の `_MEASURE.md` にも足す）。
- OCRが無い状態でも**G1は動かせる**（従来どおり画像から読む）。その場合は
  「このページのOCRは無い」と指示に明記する。黙って渡さないのが一番悪い。

## G1への文面（per-runの指示にそのまま貼る）

> ## 📝 OCRの下書きがあります
> `<作業フォルダ>/ocr/` に、**あなたの担当ページだけ**のOCRを置いてあります（PDFページ番号つき）。
> - **これは下書きで、原本ではありません。**Cloud Visionの自動読み取りなので、
>   記号の落ち（`＝`が消える）・行の欠け・`(1)`を`(I)`と読むなどの誤りがふつうに混ざります。
> - **使ってよいこと**：どのページに何があるか探す／転記のたたき台にする／
>   自分が写した文とOCRを見くらべて、写しもれに気づく。
> - **必ず原本画像と照合すること**：設問の原文・数値・選択肢・印刷された解法・答え。
>   **照合していない文をJSONに入れない。**
> - **図はOCRに写りません。**図のSVG化は今までどおり画像を見て描く。
> - **検算も今までどおり**、自分で解いて印刷された答えと突き合わせる（OCRは根拠になりません）。
> - **OCRが欠けている／誤読が多いところは、直して使おうとせず画像から直接読む。**
>   OCRの修復に時間を使わないこと。

## 🚨 実測：**問題ページと解答ページでOCRの当てになり方がまるで違う**（2026-09-13・テーマ教材 第3分冊）

| | 実測したこと |
|---|---|
| **問題ページ**（p12） | **原本とほぼ一致**。設問・小問・ノンブル（`P.13`）まで取れた。落ちたのは字間の空白だけ（`135 分`→`135分`）＝**転記のたたき台として使える** |
| **解答ページ**（p6） | **分数が全滅**。`2¼`→`21/`、`4/5`→`11/13`、`2/5`→`号`、`4/25`→`25`、**`÷`が`+`になる**（`135÷60`→`135 +60`）。答えも式も別物になる |

**理由**：この教材は分数が縦に組まれていて、OCRは上下の数字を横一列に並べ直してしまう。
→ **答え・印刷された解法は、OCRを見ずに画像から読む。**OCRを使ってよいのは
「どのページに何番があるか」「本文（文章）の下書き」まで。
⚠ 別の教材では `(1)` が `(I)` に化けた例もある。**番号・記号・数値は必ず画像で確かめる。**

## 注意（この工程で増えた失敗のしかた）

- ⚠**OCRを写して「原本どおり」と思いこむ**のが一番危ない。OCRは黙って間違える。
  → だから `kenzan` 欄は**自分で解いた結果**であって、OCRと合ったかではない。
- ⚠**OCRの誤字を直す作業に時間を溶かす**。読めないなら画像を見るほうが速い。
- ⚠ページ番号のずれ（印刷ノンブルとPDFページ）。`ocr_pages.py` が扱うのは**PDFの物理ページ**。

# ① 解法の突き合わせに使うとき（**こちらが導入の目的**）

**なぜ要るか**：原簿の `- 解法:` は、原本の解答冊子に印刷された筋をそのまま写す決まり
（→ memory `feedback_genbo_dori` ④「解法を別の筋に変えない」）。
ところが**自力の解き方に書きかえてしまう癖**が過去に出ており、実装ずみの大問にも紛れている。
**全部を画像で読み直すのは現実的でない**（トークンが際限なくかかる）ので、
**解答冊子をOCRして、原簿の解法の式が実際に出てくるかを機械で見る。**

```bash
# 解答冊子をまるごと取る（外部送信。実行前に本人へ報告）
python scripts/ocr_pages.py fetch "<解答PDF>" 1-137
# 原簿と突き合わせて、怪しいものだけ拾う
python scripts/ocr_match.py kaihou
```

- **これは「白か黒か」を決める道具ではない。**OCRは黙って間違えるので、
  **食いちがいと出たものを次の段で画像で確かめる。**（安全側：見落としより空振りを取る）
- 記録は `docs/_genbo/_KAIHOU_LEDGER.md`（1行＝1回ぶん。**数は書かず、確かめた範囲を書く**）。
- 📍**残高**：原簿で `- 解法:` を持つのは3,486本。**確かめたのは演習教材の220本だけ**。
  多い順に 小5最レ928本／小4マスター777本／小3マスター…。**まだ1本も確かめていない教材がある。**
