# G23（判断担当）の入出力ガイド

**このガイドだけで仕事が終わる形にしてあります。`scripts/` の中身を読む必要はありません。**
（2026-09-13の実測：判断担当が道具のソース3本を読んだだけで、戻り字数の48%＝36,287字を使っていた）

---

## あなたの仕事

G1が原本から取りきったデータ（設問・答え・印刷された解法・図）を読み、**判断だけ**を2つのパッチに出します。

| 出すもの | 中身 | 向き先 |
|---|---|---|
| `patch/g2.json` | 骨・コア発見・設定・作問メモ | **原簿**（大人が読む資料） |
| `patch/g3.json` | 題・分類・難しさ・**小問の対応づけ**・子ども向け解説 | **アプリ**（子どもが解く画面） |

## 🚫 出さないもの（**機械が入れます**）

**設問の文／答えの文字列／SVG本文。**
あなたが書くと同じものが2か所に増え、どちらが正しいか分からなくなります。
答えは `ref_aid` などの**IDで指すだけ**です。

## 📖 読むもの・読まないもの

| | |
|---|---|
| **読む** | 担当する `g1/*.json`（全部）と、このガイド |
| **読まない** | `scripts/` のソース／G1の作業ログ `*_log.md`／本番の `data/` `js/`／原簿本体 |
| **図** | 解説を書くのに図の中身が要るなら、`svg_ref` の指すファイルを開いて**見てよい** |

> 🚨 **「SVGを再転記しない」と「図を見なくてよい」は別のことです。**
> 見るのは可。**写すのが不可**。図を見ずに「補助線を引く」と書けないなら、見てください。

# 1. `patch/g2.json` の形

```json
{
 "TRIAL-T3-26-1-1": {
   "midashi": "小5 算数 テーマ教材 第3分冊 No.26 テーマ1 平行線と角 1-1（平行線にはさまれた折れ線の角x）",
   "hone": "平面図形（平行線と角。錯角。折れ点に平行な補助線を1本引く）",
   "core": "角xの頂点を通る、lとmに平行な線をもう1本引く。するとxが上下2つの角に分かれ、…",
   "settei": "直線 l と m が平行で、その間を折れ線が1回折れて渡っている。図に印刷されている角は35度と55度の2つだけ。",
   "kaihou_hosoku": null,
   "sakumon_memo": null
 }
}
```
- 全部 文字列 か `null`。**6つのキーをすべて置く**（中身が無ければ `null`）。
- `hone`・`core` は **印刷された解法（`kaihou_insatsu`）の筋**に沿って書く。自分の別解で上書きしない。
- 印刷された解法が `none`（原本に式が無い）なら、補う一手を `kaihou_hosoku` に書いてよい。
- `midashi` に**印刷されていない語**を入れない（教材に無い「練習問題3」などの見出しを作らない）。
- G1の `notes`（傷・未印刷・ノンブル無し）で作問担当に伝えるべきことは `sakumon_memo` へ。

# 2. `patch/g3.json` の形

```json
{
 "TRIAL-T3-26-1-1": {
   "title": "平行線にはさまれた角",
   "category": "zu",
   "unit": "平面図形（角度）",
   "star": 2,
   "steps": [
     {"ref_aid": "a1", "ref_qid": null, "ref_vid": null, "take_unit": "度",
      "kind": "numpad", "choices": null,
      "meaning": "角xの頂点を通って、直線l・mと平行な線を1本ひく。すると…"}
   ],
   "exclusions": []
 }
}
```

### 使ってよい語
- `category` … `zu`（図形）／`kazu`（数の性質・日暦）／`keisan`／`tokusan`（特殊算）／
  `kisoku`（規則性）／`hayasa`（速さ）／`wariai`（割合・比）／`baai`（場合の数）／`rittai`（立体）
- `unit` … 日本語の単元名（例 `日暦算` `速さ` `旅人算` `時計算` `平面図形（角度）` `図形の性質`）
- `star` … 難しさ **1〜4**（1＝やさしい、4＝最難）
- `kind` … `numpad`（数を打つ）／`choice`（選ぶ。このときだけ `choices` に配列）

# 3. 参照のしかた（**IDで指す**）

| キー | 意味 | 必須 |
|---|---|---|
| `ref_aid` | G1の答えの枠 `a1` `a2` … | **必須** |
| `ref_qid` | 印刷された小問 `q1` … 。印刷された小問文が無ければ `null` | 必須（nullでよい） |
| `ref_vid` | 枠の中が印刷ラベルで2つ以上に分かれているとき（`v1`＝上り など） | 無ければ `null` |
| `take_unit` | 枠から**その単位が付く値だけ**を答えにするとき | 無ければ `null` |

**`ref_qid` は、その枠 (`aid`) が持つ `qid` と一致していなければなりません。**（枠 `a2` の `qid` が `q2` なら `ref_qid` は `q2` か `null`）

# 4. 回答の分割

- **回答箇所＝枠（`aid`）**。ただし枠に `values` があるときは、**値（`vid`）ごとに1か所**。
- **すべての回答箇所を、`steps` に入れるか `exclusions` に入れるか、どちらかにする。**どちらでもないものが1つでもあると、その大問は未完成になります。
- **1つの枠を2つ以上の step が使うなら、`ref_vid` か `take_unit` で必ず区別する。**
  区別が無いと、2つの小問に同じ答えが入ってしまうため機械が止めます。

### `exclusions`（意図的に外す）
```json
"exclusions": [{"aid":"a1","vid":null,"label":"(1)",
                "reason":"図が未印刷で、その図が無いと解けないため","source":"G1の figures f1（state=unreadable）"}]
```
- 5つのキーすべて必須。`reason` と `source` が空だと止まります。
- **根拠はG1が記録したことだけ**（図が `unreadable`／答えが `unread` など）。
  「難しそう」「入れなくてよさそう」で外さない。外す理由が無いなら外さない。

# 5. 単位の扱い

- `take_unit` に書けるのは、**その枠の `unit_index` にある鍵だけ**。自分で作らない。
- 鍵の形（G1が機械で作っています）
  | 印刷された答え | `unit_index` | `take_unit` に書く |
  |---|---|---|
  | `9時40分` | `{"時":"9","分":"40"}` | `"時"` か `"分"` |
  | `時速3km` | `{"時速km":"3"}` | `"時速km"`（**接頭語ごと**。`km` だけは不可） |
  | `9分後` | `{"分後":"9"}` | `"分後"`（**経過の「後」ごと**） |
  | `3と3/5時間後` | `{"時間後":"3と3/5"}` | `"時間後"`（帯分数はこのまま1つの数） |
  | `113日間` | `{"日間":"113"}` | `"日間"` |
  | `12月1日木曜日` | `{"月":"12","日":"1","曜日":"木曜日"}` | `"月"` `"日"` `"曜日"` |
  | `月曜日` | `{"曜日":"月曜日"}` | `"曜日"` |
  | `15` | `{}` | `null`（単位が無い＝枠まるごと） |

  🚨 **`曜日` のように、取り出した値が数でない鍵もあります。**その場合はテンキーに乗らないので
  `kind:"choice"` にし、`choices` に**正解を知らなくても作れる集合**（曜日なら日〜土の7つ）を置きます。
  こうすれば「12月1日木曜日」のような答えを、`月`・`日`・`曜日` の**3つの問い**に分けられます。

- 🚨 **取り出した数だけが画面に出ます。その単位の表記が問いかけに残っていること。**
  `時速km` なら問いかけに「時速」と「km」の**両方**／`分後` なら「分」と「後」の**両方**。
  残らないなら `take_unit` は使わず、枠まるごと（`take_unit: null`）にしてください。
- **決めるのはあなたです。「問いかけを読んだ子どもが、何の単位で答えるのか分かるか」で決めてください。**
  - ✅ 例：「角 x の**角度**を求めなさい」→ **度で答える問い**なので `take_unit: "度"` でよい。
  - ⛔ **単語の中にたまたま単位の文字があるだけ、では根拠になりません。**
    例：「**分**数で答えなさい」の「分」を時間の `分` として使う、
    「**時**間の使い方」の「時」を `時` として使う——これらは不可。
  - 迷ったら `take_unit` を使わず枠まるごとにするか、**決めずに親へ返して**ください。
- 🚨 **機械の検査は補助です。**この検査は「その文字が問いかけの中にあるか」しか見ていないので、
  **通ったこと自体は「単位が明確だ」という根拠になりません。**通ったかどうかで判断しないでください。
  （2026-09-13、判断担当がここを読み取れず迷ったので書き足した）

# 6. 正常な例（そのまま形を写してよい）

**① 印刷された小問がある（いちばん多い形）**
```json
{"ref_aid":"a1","ref_qid":"q1","ref_vid":null,"take_unit":null,
 "kind":"numpad","choices":null,"meaning":"向かい合って進むと、2人が進んだキョリの和が…"}
```
**② 単位つきの答えから数だけ取り出す**（問いかけが「何**分後**ですか」なので「分」「後」が残る）
```json
{"ref_aid":"a1","ref_qid":"q1","ref_vid":null,"take_unit":"分後",
 "kind":"numpad","choices":null,"meaning":"1分間に和は80＋120＝200mずつふえるので…"}
```
**③ 答えが数でない**（テンキーに乗らないので選択肢にする。**正解を知らなくても成り立つ集合**にする）
```json
{"ref_aid":"a1","ref_qid":"q1","ref_vid":null,"take_unit":null,"kind":"choice",
 "choices":["日曜日","月曜日","火曜日","水曜日","木曜日","金曜日","土曜日"],
 "meaning":"曜日は7日ごとにくりかえすので…"}
```
> テンキーで答えられるのは **整数・小数・分数（`3/5`）・帯分数（`3と3/5`）** だけです。
> それ以外（`月曜日` `90度` など）は、`take_unit` で数にするか、`choices` を置いてください。
> **ニセの選択肢を作ってはいけません。**どちらもできないときは、決めずに親へ返してください。

# 7. 止まる例（親から差し戻されます）

| 機械が出す文 | 原因 | 直し方 |
|---|---|---|
| `aid ○ がG1に無い` | 存在しない枠を指した | G1の `kotae.slots` にある `aid` を使う |
| `qid ○ が印刷された小問に無い` | 印刷されていない小問を指した | `ref_qid` を `null` にする |
| `vid ○ が枠 ○ に無い` | その枠に `values` が無い | `ref_vid` を `null` にする |
| `答えの枠 ○ は ○ のものなのに ○ を指している` | 枠の `qid` と `ref_qid` の食いちがい | 枠が持つ `qid` に合わせる |
| `答えの枠 ○ を○個の小問が使うのに、どの値を答えるかが…` | 同じ枠を複数stepが区別なしに使った | `ref_vid` か `take_unit` を付ける |
| `単位「○」の値が答えの中で一意に決まらない` | `unit_index` に無い鍵を書いた | 表にある鍵だけ使う |
| `単位「○」で ○ を取り出したのに、問いかけに ○ が出てこない` | 単位の表記が問いかけから消える | `take_unit` をやめて枠まるごとにする |
| `回答箇所 ○ が「アプリ小問へ対応ずみ」でも「理由つきの意図的除外」でもない` | 取りこぼし | step に入れるか、根拠つきで `exclusions` に入れる |
| `除外 ○ に理由か出どころが無い` | `reason` か `source` が空 | G1の記録を根拠に書く。書けないなら外さない |
| `G3のパッチが無い` | その仮IDを書き忘れた | 担当ぶん全部を出す |
| `問いかけを原文から決められない` | 原文に小問記号も答える場所の表記も無い | **あなたの直しでは消せません。**決めずに親へ返す |
| `図 ○ の所属が確定できない` / `大問の図が○枚` | G1側の記録の問題 | **親が扱います。**触らない |

# 8. 親がやること／あなたがやらないこと

- **検証（Schema・参照整合性）と機械結合は、親がまとめて走らせます。**
  あなたは `python scripts/…` を走らせなくてよい（走らせても構いませんが、必須ではありません）。
- 失敗したときは、**対象ID・理由・必要な直し**だけが親から返ってきます。その2〜3か所だけ直してください。
- **原因が分からない止まり方は、直そうとせずそのまま報告してください。**道具の不具合は親が調べます。
- 検証のしくみを自分で作り直さない（同じ判定を別実装すると、食いちがったときに正が分からなくなります）。
